## Module dependency graph

```
AppModule
├── AuthModule (from @thallesp/nestjs-better-auth)
│   └── mounts Better Auth request handler at /api/auth/*
├── DatabaseModule  [Global]
│   ├── provides DATABASE_POOL (pg.Pool singleton)
│   └── provides DatabaseService (Drizzle wrapper)
├── PostsModule
│   ├── PostsController
│   └── PostsService  ← injects DatabaseService
└── ReactionsModule
    ├── ReactionsController
    └── ReactionsService  ← injects DatabaseService
```

`DatabaseModule` is decorated `@Global()`, so `DatabaseService` is available to every module without explicit imports.

## Request lifecycle

1. **HTTP layer** – NestJS + Express. `bodyParser` is disabled globally so Better Auth can consume the raw request body for its own routes.
2. **Auth middleware** – Requests to `/api/auth/*` are intercepted by the Better Auth handler registered by `AuthModule.forRoot()`. All other routes go through normal NestJS routing.
3. **Session guard** – `@thallesp/nestjs-better-auth` provides a `@Session()` parameter decorator that resolves the current `UserSession` from the Better Auth session. By default all routes require a valid session. Use `@AllowAnonymous()` to opt out.
4. **ts-rest handler** – Controllers use `@TsRestHandler(contract.endpoint)` and `tsRestHandler(contract.endpoint, handler)`. The handler receives typed `{ body, params, query }` and must return a typed `{ status, body }` matching the contract response schema.
5. **Service layer** – Controllers delegate all database access to services. Services call `DatabaseService.db` (a fully-typed Drizzle client) and return domain DTOs from `@repo/shared-dto`.
6. **Validation** – Input bodies are parsed with Zod schemas (e.g. `createPostSchema`) before being passed to the service. Responses are also validated against the contract schema before being returned.

## Authentication design

Better Auth is configured in `src/auth/index.ts` with:

- **`emailAndPassword`** plugin – users sign up and sign in with email + password.
- **`username`** plugin – adds a `username` field to the user.
- **`jwt`** plugin – issues short-lived JWTs in addition to session cookies, enabling stateless authentication for clients that cannot use cookies.

The Better Auth `user` table is managed entirely by Better Auth's own migrations (`better-auth_migrations/`). The application code only reads user data through a read-only Drizzle view (`users_view`) that selects `id`, `username`, `email`, and `name` from the underlying `"user"` table.

Auth routes exposed by Better Auth (under `/api/auth/*`) include:

- `POST /api/auth/sign-up/email`
- `POST /api/auth/sign-in/email`
- `POST /api/auth/sign-out`
- `GET  /api/auth/session`
- `GET  /api/auth/token` (JWT)

The ts-rest `AuthController` stubs (`/auth/login`, `/auth/me`) exist only to satisfy the shared contract type; real authentication happens via the Better Auth routes above.

## ts-rest contract integration

The shared contract is defined in `packages/auth-contracts/src/index.ts`. It is the single source of truth for:

- HTTP method and path
- Path parameters, query parameters, and request body shape
- Response status codes and response body shapes

Both the backend (`@ts-rest/nest`) and frontend (`@ts-rest/react-query` or similar) consume this contract. Adding a new endpoint requires:

1. Adding the route definition to `packages/auth-contracts/src/index.ts`.
2. Adding a `@TsRestHandler` method in the appropriate NestJS controller.
3. Implementing the service method.
4. Updating `packages/shared-dto` if a new shared DTO is needed.

## Error handling conventions

- Return typed `{ status: 404, body: null }` for not-found resources (contract-defined).
- Return `{ status: 403, body: null }` when the authenticated user is not the resource owner.
- Throw `HttpException` subclasses for unexpected errors; do not let raw `Error` objects propagate to the HTTP layer.
- Never log PII or secrets. Log request context (post ID, user ID) for debugging.

## Testing strategy

All tests are end-to-end tests (no unit tests with mocks). Each test suite:

1. Starts a real PostgreSQL container via **Testcontainers** (shared across the full test run by `global-setup.ts`).
2. Runs Better Auth migrations against the container DB.
3. Bootstraps a full NestJS application pointing at the container DB.
4. Uses the Better Auth client (`auth-client.helper.ts`) to create users and obtain sessions.
5. Makes HTTP requests via `supertest`.

This approach gives high confidence that the SQL queries, ORM mappings, and HTTP contract all work together correctly.

The `vitest.config.e2e.ts` sets `fileParallelism: false` to prevent concurrent test files from interfering with the shared database state, and raises `hookTimeout` to 120 s to accommodate container startup time.
